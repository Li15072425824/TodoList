# ego lite / ego-browser 使用指南与项目走查可行性

> 调研日期：2026-10-20
> 环境：macOS (Darwin 25.0.0, arm64)，ego-browser 0.6.0.16 / Chromium 154 / Node 24.21.0
> 资料来源：本机 `ego-browser skill`（v2.1.0）、GitHub 仓库 citrolabs/ego-lite README、lite.ego.app 官网、对 `sports-game` 的实测

---

## 0. 结论摘要

1. **ego lite 是给 AI agent 用的 Chromium 浏览器**，`ego-browser` 是驱动它的命令行/skill。人和 agent 可以并行使用同一个浏览器，agent 在独立 Space 里操作，不抢用户的标签页，并继承用户的登录态。
2. **它适合做浏览器内的 UI/功能走查**：真实渲染、可点击、可截图、可读语义树、可查控制台/网络/JS 异常、可用 CDP 模拟移动端和暗色模式。
3. **它不是现成的测试框架**：没有内置断言、用例管理和 CI 编排；走查的"判断标准"和"问题清单"仍需要人/模型来产出。
4. **实测 `sports-game` 可行**：已跑通 4 个 tab、桌面 / 375px / 暗色三种视图、localStorage 持久化；截图证据见 `notes/`。
5. 局限：仅 Chromium（无跨浏览器）、仅 macOS/Windows（Linux 路线图）、验证码/权限类弹窗需用户接管、截图会带上 agent 光标。

---

## 1. 它是什么

ego lite 的定位是"**为 AI agent 设计的浏览器**"，而不是又一个浏览器自动化库：

- 基于 Chromium，可一键导入 Chrome 的书签、扩展、cookies、登录态；
- agent 的用户数据、cookie 都留在本机；
- agent 的任务跑在独立的 **Space**（隔离工作区）中，用户可以继续在自己的窗口浏览；
- 通过 `ego-browser` 暴露一套精简 API：TaskSpace、Page、snapshot、screenshot、click/fill、evaluate、CDP 等；
- 支持 Claude Code、Codex、Cursor 等能写代码的 agent。

与 Playwright / browser-use 类工具的区别：后者是"桥接"一个外部浏览器；ego lite 本身既是浏览器又是 agent 运行时，登录态和标签页可以直接继承。

## 2. 快速上手（本机已装的版本）

### 2.1 自检

```bash
command -v ego-browser
ego-browser --version
ego-browser skill        # 打印与当前版本匹配的完整用法指南
```

### 2.2 三种使用方式

**方式 A：自然语言（最常用）**

直接在 Claude Code 里说"用 ego-browser 打开 xxx / 帮我填 xxx / 走查一下这个页面"，agent 会加载 ego-browser skill 并执行。若已注册斜杠命令，也可以 `/ego-browser` 开头描述任务。

**方式 B：内联脚本**

```bash
ego-browser nodejs <<'EOF'
const task = await taskSpace("inspect example page");
const page = task.page("p1");
await page.goto("https://example.com");
console.log(await page.snapshot());
EOF
```

**方式 C：多轮任务用 `.mjs` 文件**

每一轮都是**新进程**，变量不保留，但 TaskSpace、Page 标签会保留。多轮任务建议每轮写一个新的完整文件（`round-01.mjs`、`round-02.mjs`…），用 `taskSpace(spaceId)` 恢复同一个空间。

### 2.3 核心概念

| 概念 | 说明 |
|---|---|
| `taskSpace(name)` | 一个用户目标对应一个 TaskSpace；同名会恢复已有空间 |
| `task.page("p1")` | Page 有永久标签（p1、p2…），跨轮次可用 |
| `snapshot()` | 把页面转成结构化的可访问性树文本，适合让模型理解页面并生成选择器 |
| `screenshot()` | 截图到绝对路径；用于视觉确认 |
| 选择器 | `@ref`、`text=...`、`loc=css:`、`loc=role:`、`xpath=`、原生 CSS |
| `page.evaluate()` | 在页面里执行 JS，适合批量提取数据 |
| `page.cdp()` | 底层 Chrome DevTools Protocol，兜底手段 |
| `task.finish()` | 任务结束时关闭 agent 页面 |

### 2.4 必知规则

- 每个脚本独立进程；状态在 TaskSpace/Page，不在 JS 变量里。
- 所有文件路径用**绝对路径**；脚本不继承 shell 的环境变量。
- 它不是 Playwright：不要臆造 `locator()`、`expect()`、`route()` 等方法，用文档里列出的 API + `evaluate/cdp` 兜底。
- 一次观察尽量只取一种状态：语义页面用 snapshot，canvas/富文本用 screenshot。
- 验证码、设备选择器、权限弹窗需要 `task.handOff()` 交给用户处理。

## 3. 能做什么

| 场景 | 说明 |
|---|---|
| 读取/总结网页 | 包括登录后才可见的页面，免去重新登录 |
| 填写表单、后台操作 | 点击、输入、下拉、上传文件、处理弹窗 |
| 抓取结构化数据 | `page.evaluate()` 批量提取，支持分页 |
| 截图与视觉验收 | 桌面/移动端/暗色模式截图，生成报告素材 |
| UI 走查 / QA / dogfooding | 点完整流程、异常分支、刷新恢复、检查控制台与网络 |
| Canvas / 富文本 / 地图 | 用截图 + 鼠标键盘坐标操作 |
| 调试 | 读取 DOM、执行 JS、CDP 抓网络与异常 |
| 下载/上传 | 拦截 download 事件并保存到指定路径 |

### 3.1 官方给出的效果数据

来自 lite.ego.app / GitHub README（厂商自测，未独立验证）：

- 复杂网页任务比对比工具快 **47%–63%**；
- 平均每任务耗时：ego-browser **398s**，chrome-devtools-cli 587s，agent-browser 605s，browser-harness 615s，playwright-cli 648s；
- 卖点是"更快、更少的失败、更少的 token"，语义快照在自家 Chromium 引擎内生成，比注入脚本方案更稳。

### 3.2 实际体感（本次实测）

- 打开本地页面、抓语义快照、截图都是秒级；
- 语义快照能直接给出按钮/标题/DOM 结构，生成选择器很顺；
- 用 CDP `Emulation.setDeviceMetricsOverride` 切 375px、`setEmulatedMedia` 切暗色都有效；
- 页面里的随机 toast、canvas 图表都能截到；
- 局限：截图里会出现 ego 的 agent 光标头像，做像素级对比时要注意。

## 4. 项目走查：能不能做？

### 4.1 结论

**能，而且很适合。** 浏览器内的功能、交互、视觉、技术四类走查都能覆盖。它不是"自动发现问题"的魔法，而是"能可靠地操作 + 观察 + 取证"的执行器；问题判定需要明确的走查清单和验收标准。

### 4.2 建议的走查清单

**A. 功能**
- 主流程能否从入口走到终点
- 每个 tab / 路由 / 弹窗是否能打开、关闭、返回
- 空状态、加载态、错误态
- 刷新、后退、重复提交后的状态
- localStorage / 后端数据是否持久化、是否串档

**B. 视觉**
- 1440 / 1280 / 768 / 375 宽度
- 暗色模式 / 浅色模式
- 长文本、超长列表、极端数值
- 对齐、溢出、遮挡、hover/focus 可见性

**C. 交互**
- 表单校验与错误提示
- 键盘操作（Tab、Enter、Esc）
- 按钮禁用/加载/重复点击
- 上传、下载、文件选择

**D. 技术**
- 控制台报错、未捕获异常
- 失败请求、404 资源、接口状态码
- 可访问性树是否合理（snapshot 可直接看角色/名称）
- viewport、meta、语言、标题
- 性能粗查（CDP / Performance）

**E. 证据与产出**
- 每个问题：截图 + 页面 URL + 复现步骤 + 期望/实际 + 严重级别
- 截图放 `notes/`，报告写 `调研报告.md`

### 4.3 不能替代的部分

- **设计审美与品牌一致性**：需要人给标准，或对比设计稿；
- **跨浏览器**：只有 Chromium，Safari/Firefox 需另测；
- **原生 App / 桌面端**：不覆盖；
- **压力/安全测试**：不是它的定位；
- **自动断言与 CI**：可以脚本化，但断言、用例组织要自己写；
- **验证码、系统权限、设备选择**：需用户 handoff。

| 训练周 | ✅ 7 天卡片、推荐计划/开始本周/上周复盘/新开档按钮齐全 |

| 暗色模式 | ✅ 变量切换正常 |
| 状态持久化 | ✅ 刷新后仍是第 2 周、知识 5/21（localStorage 生效） |
| 宽屏居中 | ✅ 实测 `.wrap` 宽 960，在 2011 视口中 x=525.6，确实居中 |

### 5.3 发现的可优化点（非阻断）

1. **375px 下按钮换行**："推荐计划 / 开始本周 / 上周复盘"占一行，"新开档"单独一行；可用性没问题，视觉上可再收一收。
2. **移动端底部 toast 与页脚免责声明短暂重叠**：toast 消失后恢复，属于瞬时遮挡。
3. **截图中出现 ego agent 光标头像**：这是 ego lite 的界面元素，不是页面 bug；做视觉基线对比时需要排除。
4. **尚未覆盖**：完整一周执行、事件/执行题弹窗、比赛日动画、控制台报错、失败请求、刷新中断恢复。这些是下一轮走查的重点。

## 6. 建议的走查 SOP

1. **定范围**：目标项目/页面、走查深度（快速体检 / 全流程 / 发版前回归）、验收标准。
2. **起服务**：静态页用 `python3 -m http.server`；Vue 项目 `npm run dev`（`vue3-todolist` 默认 5173）。
3. **建一个 TaskSpace**，按页面/角色/流程分轮，每轮截图 + 快照。
4. **技术检查**：监听 console/网络异常（CDP 或 `page.events()`），记录失败请求。
5. **多视图**：CDP 模拟 375 / 768 / 1440，暗色模式各截一张。
6. **交互回归**：主流程 + 异常分支 + 刷新恢复 + 重复操作。
7. **汇总**：问题按 P0/P1/P2 分级，附截图、复现步骤、期望/实际。
8. **归档**：报告写 `PPT/<topic-slug>/调研报告.md`，证据放同目录 `notes/`。

### 6.1 走查脚本骨架

```js
const task = await taskSpace("walkthrough-<project>-<date>");
const page = task.page("p1");
await page.goto("http://127.0.0.1:5173/");
console.log(await page.snapshot());
console.log(await page.screenshot({ path: "/abs/path/notes/home.png" }));

// 移动端 + 暗色
await page.cdp("Emulation.setDeviceMetricsOverride", {
  width: 375, height: 844, deviceScaleFactor: 2, mobile: true,
});
await page.cdp("Emulation.setEmulatedMedia", {
  features: [{ name: "prefers-color-scheme", value: "dark" }],
});
await page.reload();
console.log(await page.screenshot({ path: "/abs/path/notes/home-375-dark.png" }));

// 恢复
await page.cdp("Emulation.setEmulatedMedia", { features: [] });
await page.cdp("Emulation.clearDeviceMetricsOverride");

// 结束
await task.finish({ keep: [] });
```
